# Standalone switcher validation

Validation was performed on macOS 27, Apple Silicon. Session output, application inventories, process IDs, display names, and workstation paths are deliberately excluded from this document.

- SwiftPM: **101 tests passed** (31 core and 70 app tests), covering partial/total minimization, restoration with stale tags, helper windows, closed-but-retained windows, unknown states, independent hidden/minimized/windowless filters, negative display coordinates, multi-display geometry, and live selection updates. Regressions also cover hidden windows without visibility history, keyboard recovery failure and retry, and preview conversion for both keyboard directions and Command release using in-memory events. Added review regressions reproduce mouse/external closure, rejected openings, consumed key-up pairing, rapid consecutive sessions, failure delivery across suspension for both tap-disable reasons, and reconciliation before failure delivery. Eight metadata regressions exercise floating/modal content, helpers, transparency, unknown tags, history and independent filters with actual CoreGraphics dictionary keys. The earlier failing cases were run before their corrections; the ten delivery-monitor cases below use synthetic counters rather than a reproduced physical wake failure.
- Secure Input regressions use injected lifecycle states and fake shortcut ownership: entering restores native shortcuts even when capture reports running and invalidates queued selection/confirmation; repeated checks do not repeatedly release; leaving waits for the settling interval; sleep, inactive sessions and failures remain independent. Aggregate keyboard diagnostics distinguish received events from handled shortcuts. A reported no-selector incident kept logging enabled capture without reporting a failure; its original log does not record Secure Input or callback activity, so the exact cause remains unconfirmed. Live Secure Input fallback has not yet been verified.
- A later wake incident was recorded by a still-running v0.1.4 build 8 on another Mac running macOS 26.4. Its logs never show v0.1.5 or v0.1.6 starting. After wake, the catalog remained ready and the main-loop heartbeat continued with capture and shortcut ownership reported active, but no selector opening was logged. These records do not establish a Secure Input or event-tap cause. The active build lacked the newer protection and aggregate callback diagnostics. Raw incident logs remain local.
- Ten new delivery-monitor regressions use injected aggregate counters and fake shortcut ownership. They cover no hardware-counter reads while inactive, an enabled but silent capture, restoration before reacquisition, a failure latch across wake and explicit retry, a single missed key followed by waiting, idle/unavailable counters, unequal deltas, received autorepeat, callback grace, repeated missed input, pause/rearming, counter wrap/reset, clock reset and delayed main-loop samples. The monitor reads only aggregate HID key-down activity and never requests another permission or inspects key contents. Physical verification on the affected Mac remains pending.
- The previous release's SwiftPM suite passed on a mounted **case-sensitive APFS** volume, verifying the exact lowercase test-target paths.
- Shortcut ownership regressions use file-backed fake shortcut states and real child processes. They cover both exit orders, denied ownership, guardian startup failure, unexpected guardian exit, and SIGKILL of a disposable owner. A delayed guardian verifies that another owner cannot acquire until fallback restoration finishes. No real system shortcuts are changed by these tests. Additional regressions cover a hung owner detected by the guardian heartbeat, deferred keyboard actions, ordinary keys after queued confirmation, pending action invalidation, independent sleep/session reasons, queries blocked across sleep, local log rotation and automatic Accessibility grant recovery without restart loops.
- Publication auditor: **41 tests passed** with synthetic index paths, empty ZIP directories, renamed and deleted historical paths sharing blobs, redacted error output, content detection, and author/committer metadata limited to public handles and GitHub noreply addresses. Annotated tags use the same public identity policy and check names, messages, additional headers and nested tags. Tag references are also checked, including aliases and lightweight tags. Independent review added regressions for paths in trees referenced only by tags and private original tag bytes hidden by local Git replacements. The current review adds raw and continued commit headers, embedded merge tags without references, original commit bytes hidden by replacements, and ISO-8859-1 messages with synthetic accented identity hints. The newly rejected cases failed before correction; public embedded tags remain accepted. All reads disable replacements to inspect the objects Git publishes. All rejected fixture values remain absent from diagnostics.
- A disposable native app built with the current extractor and core filter verified three real visible content windows: floating NSWindow, modal NSWindow and floating NSPanel. Each had on-screen CoreGraphics metadata and remained eligible with default filters. The panel was configured to stay visible on deactivation; a panel that hides on deactivation correctly did not count as visible. No Accessibility grant, global event tap or native shortcut changes were used by this probe.
- An earlier real own-window probe passed **11 checks** for visible, partially minimized, fully minimized, minimized-filter-disabled, restored, hidden-filter-enabled, hidden-filter-disabled, unhidden, closed-window states, and cold-start hidden with one/all windows minimized. Hidden state was checked with `NSRunningApplication.current.isHidden`. A later recheck failed at the closed-window stage, including when running that earlier executable; the current recheck must not be reported as 11/11.
- SkyLight symbols and minimization tags were available. Visible-window history handles nonuniform user-window markers. Closed-but-retained NSWindows do not incorrectly keep minimized apps in the selector.
- The single-row panel, neutral highlight, selected-app label, English settings, and four independent filter checkboxes were inspected in the UI. Clicking a preview icon activated the target and closed the panel. Filter values were saved independently. The redesigned settings were inspected with Accessibility missing and granted; the permission action disappears after a live grant. Pausing and resuming updated the displayed state and released/reacquired native shortcut ownership.
- v0.1.8 adds a flat application icon with two windows and a Tab arrow. The reviewed 1024 px RGBA source contains only IHDR/sRGB/IDAT/IEND chunks. macOS converted it to all ten 16–1024 px icon representations and decoded the resulting ICNS successfully; the 64 px representation was inspected. The packaged app was opened with Accessibility ungranted; Settings displayed the new icon next to the title, and the menu/footer displayed v0.1.8 build 12 without clipping. It was closed after inspection. A pinned SHA-256 allows only the reviewed artwork bytes as binary source. Six auditor regressions cover exact artwork, modified bytes, other binaries, private historical renames, invalid-byte boundaries and contiguous private strings in binary data.

An unmodified copy of the published v0.1.7 app found v0.1.8 through **Check for Updates…**, downloaded it from GitHub, and completed **Install and Relaunch**. Its bundle became v0.1.8 build 12 with matching icon bytes and valid nested signatures; the relaunched Settings showed the new icon and version. This disposable copy was closed afterward. No Accessibility grant or changes to the other Mac were made.
- v0.1.9 uses a custom 18 pt vector template in the menu bar matching the two-window Tab mark. Native and enlarged renderings were inspected on light/dark backgrounds, including its update dot. - v0.1.10 replaces ad hoc release signatures with a persistent self-signed code certificate kept in the login Keychain. No Developer ID was available. No certificate trust, Gatekeeper or TCC settings were changed to sign it. Two separately compiled executables with different bytes shared the same designated requirement and passed cross-validation; ad hoc code, a different identifier and modified bytes were rejected. The main app and all nine nested code objects passed certificate SHA-256, strict signature, full requirement, identifier and flag checks. Release packaging rejects an explicit ad hoc mode and never creates a replacement key. Seven public-only requirement regressions reject added alternatives (including another line), other pins/identifiers, hash-only identity, duplicate requirements and a changed main certificate position. The Python suites now contain **68 passing tests**; Swift remains **101 passing tests**. The initial transition from ad hoc can require renewing Accessibility; physical grant retention on the other Mac remains unverified.
- Six updater-state regressions exercise real Sparkle delegate methods without starting scheduling or network requests: downloaded and prepared updates survive dismissal, skipped/canceled updates clear their reminders, and stale callbacks cannot replace a newer prepared update.
- Nine archive regressions preserve framework symlinks and executable modes, reject escapes/cycles/dangling links and entries beneath a symlink, and verify deterministic metadata. Four added auditor regressions enforce the framework boundary and scan symlink payloads without exposing rejected values. A real framework ZIP was extracted with `ditto`; nested helpers stayed executable and `codesign --verify --deep --strict` passed.
- Eleven public-key verifier regressions pass using ephemeral CryptoKit fixture keys, without Keychain access. They reject altered feed/archive bytes, wrong keys, inconsistent lengths, missing/duplicate archive signatures, unsigned XML tails, DOCTYPE and malformed UTF-8. A reproduced UTF-8 replacement bypass failed before correction and passes after requiring the original bytes to survive UTF-8 decoding unchanged. Together the Python publication, archive and signature suites pass **61 tests**.
- An isolated integration copy with a distinct bundle identifier automatically fetched a signed feed and ZIP from a localhost server, showed **Install Update 0.1.7…**, and installed on quit: its bundle changed from build 10 to build 11 with nested signatures valid. No Accessibility grant or native shortcut changes were used. The local HTTP endpoint was limited to this disposable test; production uses HTTPS GitHub URLs and pins the signing key. ## Remaining runtime verification

The own-window recheck currently stops after the unhidden stage: AppKit reports both retained test windows closed and invisible, while CoreGraphics still reports a window on screen. A separate query process sees the same result. Waiting before closing, explicitly ordering windows out, and a control closing without minimization or hide/unhide did not resolve it. Independent review reproduced the failure with the previous executable and found no blocking defect attributable to the reviewed changes. The cause of the AppKit/CoreGraphics disagreement remains undetermined; closed-window and subsequent cold-start checks need revalidation. No assertion was weakened to obtain a passing result.

Physical sleep/wake verification of the recovery changes is pending. Permission-cache recovery is covered with injected permission states; a live grant transition requires OS authentication.

Physical-keyboard confirmation of ⌘Tab, ⌘⇧Tab, release-to-activate, and Esc is pending. Computer-use synthetic key presses did not reach the global event tap and cannot substitute for that check.

Multi-display geometry is covered by unit tests; verification with a second physical display is pending. Compatibility outside the tested macOS version and architecture is unverified. The release is experimental and is not notarized.

Window tags can retain a hidden marker after closing a window while the app is hidden. Such ambiguous metadata remains eligible until it resolves; the cold-start policy favors keeping an app reachable. Ordinary closed-window markers and invisible helpers remain excluded.

The app does not change installed applications, Dock.app, SIP, or the symbolic-hotkey preferences file. Native shortcut changes are temporary and are restored when the app is paused, quits, or the main process is force-quit.
