# Standalone switcher validation

Validation was performed on macOS 27, Apple Silicon. Session output, application inventories, process IDs, display names, and workstation paths are deliberately excluded from this document.

- SwiftPM: **85 tests passed** (31 core and 54 app tests), covering partial/total minimization, restoration with stale tags, helper windows, closed-but-retained windows, unknown states, independent hidden/minimized/windowless filters, negative display coordinates, multi-display geometry, and live selection updates. Regressions also cover hidden windows without visibility history, keyboard recovery failure and retry, and preview conversion for both keyboard directions and Command release using in-memory events. Added review regressions reproduce mouse/external closure, rejected openings, consumed key-up pairing, rapid consecutive sessions, failure delivery across suspension for both tap-disable reasons, and reconciliation before failure delivery. Eight metadata regressions exercise floating/modal content, helpers, transparency, unknown tags, history and independent filters with actual CoreGraphics dictionary keys. The failing cases were run before their corrections.
- Secure Input regressions use injected lifecycle states and fake shortcut ownership: entering restores native shortcuts even when capture reports running and invalidates queued selection/confirmation; repeated checks do not repeatedly release; leaving waits for the settling interval; sleep, inactive sessions and failures remain independent. Aggregate keyboard diagnostics distinguish received events from handled shortcuts. A reported no-selector incident kept logging enabled capture without reporting a failure; its original log does not record Secure Input or callback activity, so the exact cause remains unconfirmed. Live Secure Input fallback has not yet been verified.
- The previous release's SwiftPM suite passed on a mounted **case-sensitive APFS** volume, verifying the exact lowercase test-target paths.
- Shortcut ownership regressions use file-backed fake shortcut states and real child processes. They cover both exit orders, denied ownership, guardian startup failure, unexpected guardian exit, and SIGKILL of a disposable owner. A delayed guardian verifies that another owner cannot acquire until fallback restoration finishes. No real system shortcuts are changed by these tests. Additional regressions cover a hung owner detected by the guardian heartbeat, deferred keyboard actions, ordinary keys after queued confirmation, pending action invalidation, independent sleep/session reasons, queries blocked across sleep, local log rotation and automatic Accessibility grant recovery without restart loops.
- Publication auditor: **31 tests passed** with synthetic index paths, empty ZIP directories, renamed and deleted historical paths sharing blobs, redacted error output, content detection, and author/committer metadata limited to public handles and GitHub noreply addresses. Annotated tags use the same public identity policy and check names, messages, additional headers and nested tags. Tag references are also checked, including aliases and lightweight tags. Independent review added regressions for paths in trees referenced only by tags and private original tag bytes hidden by local Git replacements. The current review adds raw and continued commit headers, embedded merge tags without references, original commit bytes hidden by replacements, and ISO-8859-1 messages with synthetic accented identity hints. The newly rejected cases failed before correction; public embedded tags remain accepted. All reads disable replacements to inspect the objects Git publishes. All rejected fixture values remain absent from diagnostics.
- A disposable native app built with the current extractor and core filter verified three real visible content windows: floating NSWindow, modal NSWindow and floating NSPanel. Each had on-screen CoreGraphics metadata and remained eligible with default filters. The panel was configured to stay visible on deactivation; a panel that hides on deactivation correctly did not count as visible. No Accessibility grant, global event tap or native shortcut changes were used by this probe.
- An earlier real own-window probe passed **11 checks** for visible, partially minimized, fully minimized, minimized-filter-disabled, restored, hidden-filter-enabled, hidden-filter-disabled, unhidden, closed-window states, and cold-start hidden with one/all windows minimized. Hidden state was checked with `NSRunningApplication.current.isHidden`. A later recheck failed at the closed-window stage, including when running that earlier executable; the current recheck must not be reported as 11/11.
- SkyLight symbols and minimization tags were available. Visible-window history handles nonuniform user-window markers. Closed-but-retained NSWindows do not incorrectly keep minimized apps in the selector.
- The single-row panel, neutral highlight, selected-app label, English settings, and four independent filter checkboxes were inspected in the UI. Clicking a preview icon activated the target and closed the panel. Filter values were saved independently. The redesigned settings were inspected with Accessibility missing and granted; the permission action disappears after a live grant. Pausing and resuming updated the displayed state and released/reacquired native shortcut ownership.
- The windowless filter was toggled in the installed app: preview contained nine apps with it disabled and seven with it enabled. Local health logs confirmed Accessibility trusted, active capture and native shortcut ownership after refreshing the existing grant. OpenVPN was not running, so its particular window behavior has not been verified.
- Accessibility enabled the session event tap. Replacing an ad hoc signed build required removing and re-adding the current bundle; reopening the same build retained permission.
- `--native-status` reported both native shortcuts disabled while CmdTabo was active and enabled after pausing.
- A forced termination of the main process caused the temporary guardian to restore both native shortcuts and exit. Reopening CmdTabo disabled them again.
- Package signature, plist, archive and publication validation passed. The archived injection prototype's trial also passed with zero failures. Only the standalone app is included in release archives; the injection prototype is not loaded.

## Remaining runtime verification

The own-window recheck currently stops after the unhidden stage: AppKit reports both retained test windows closed and invisible, while CoreGraphics still reports a window on screen. A separate query process sees the same result. Waiting before closing, explicitly ordering windows out, and a control closing without minimization or hide/unhide did not resolve it. Independent review reproduced the failure with the previous executable and found no blocking defect attributable to the reviewed changes. The cause of the AppKit/CoreGraphics disagreement remains undetermined; closed-window and subsequent cold-start checks need revalidation. No assertion was weakened to obtain a passing result.

Physical sleep/wake verification of the recovery changes is pending. Permission-cache recovery is covered with injected permission states; a live grant transition requires OS authentication.

Physical-keyboard confirmation of ⌘Tab, ⌘⇧Tab, release-to-activate, and Esc is pending. Computer-use synthetic key presses did not reach the global event tap and cannot substitute for that check.

Multi-display geometry is covered by unit tests; verification with a second physical display is pending. Compatibility outside the tested macOS version and architecture is unverified. The release is experimental and is not notarized.

Window tags can retain a hidden marker after closing a window while the app is hidden. Such ambiguous metadata remains eligible until it resolves; the cold-start policy favors keeping an app reachable. Ordinary closed-window markers and invisible helpers remain excluded.

The app does not change installed applications, Dock.app, SIP, or the symbolic-hotkey preferences file. Native shortcut changes are temporary and are restored when the app is paused, quits, or the main process is force-quit.
